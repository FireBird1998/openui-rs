# Conformance

The `openui-lang` crate is a port of the OpenUI Lang language layer in `@openuidev/lang-core`, the **reference**. Conformance means that for the same input, the core's output is exactly the reference's: byte for byte, not "equivalent".

- **Parse results:** `ParseResult::to_json()` equals `JSON.stringify` of the reference's result, for one-shot parsing and after every push of a streaming parse, with both sides cutting the text at the same code points.
- **Everything else:** the same system prompt string, the same merged program text, the same source from `jsonToOpenUI`, the same enriched errors. Where the reference throws, the core returns an error.

The reference is lang-core 1.1.0 (OpenUI Lang 1.1), and the core matches it on every case in the corpus: nothing is pending. The quirks and divergences below were checked against 1.1.0 on 2026-11-06, and quirks 21 and 22 added on 2026-11-07. Three quirks were fixed upstream in 1.1, and the core follows. The core conformed to 1.0.1 and to 0.3.0 before; those states are the local tags `lang-core-1.0.1` and `lang-core-0.3.0`, and aren't kept up.

Behaviour that looks wrong in the reference is reproduced anyway and recorded as a [quirk](conformance/QUIRKS.md) with a draft upstream report. The core and runtime depart from the reference only where the list of [divergences](#divergences) below says so. The runtime representation divergences include nested undefined and function-valued state.

`reference/runtime.ts` runs the pinned parser, store and tree evaluator, with
synchronous implementations for every declared function and the schema's action definitions.
`conformance/function-implementations.json` selects shared pure-JSON recipes,
implemented in `reference/function-implementations.ts` and the Rust harness's

Schema cannot carry upstream's in-memory binding marks. `conformance/bindings.json`

The `BindingTypes` fixture uses live upstream Zod schemas for marked arrays
and unions and for unmarked arrays/unions with marked children. A binding
wrapper must enclose the whole annotation: `$binding<T>[]` marks an item,
while `$binding<T[]>` marks the prop.
Every component prop in every corpus schema is checked against those live marks
by `BindingProps::from_prompt_spec`. Specs cannot recover absent annotations,
identity changes after spec generation, or marks on schemas whose type could
not be rendered. Embedders can supply the component/prop pairs directly.
Property names in the spec's `schema.$defs` anchor individual annotations.
The live `SignatureOdd` fixture checks punctuation in names and upstream's
unescaped quote/backslash literal text. Repeated parameter delimiters in
literal text, and delimiter names such as `a, b` alongside `b`, can be ambiguous.
`BindingProps::undecided()` reports each affected component/prop pair; an
unreadable outer binding wrapper is reported independently and later fields
still resolve. The live `binding-undecided-spec.json` fixture pins E10's quoted
literal, E11's backslash literal, the delimiter collision and an unambiguous
delimiter name. Every upstream mark there is either recovered or explicitly
reported as undecided, and no recovered mark is wrong. `insert` resolves a
reported pair as a binding; `remove` resolves it as not a binding. Ambiguous
signature-only delimiters or repeated names report the recognized candidates
as undecided and never mark them. Without structural properties only well-formed,
ordinary-name signatures are reliable, and diagnostics cannot enumerate names
hidden by malformed signature-only text. Structural names with missing or
malformed signatures are reported as undecided. The tree harness refuses
undecided configurations for its ordinary corpus schemas.

reference adapter uses lang-core's actual `createQueryManager(null)`, registers

The embedder's extra cache-key values are upstream's `extraDeps`. The
adapter looks them up by the tool name coerced to a string, as a property of

A query is loading while its current entry has a call in flight. Delivery of a
successful result to that entry gives the query a fetch history. In
`displaying-another-query-result`, displaying a result still held by a
different query leaves that history untouched. Only the first query refetches
until the second receives a successful completion of its own.

In `reader-waits-for-its-input`, the reader's arguments use the source query.
Rust dispatches both calls on the first evaluate, with a null input for the
reader. Lang-core dispatches the source first, then dispatches the reader with
the source result on completion. This divergence is temporary until #86.

The original corpus supplies 127 action cases; the added cases exercise fresh

Run steps are host handoffs: `{type:"run",params:{statementId,refType},
humanFriendlyMessage:"",formState,formName}`; mutations additionally put their
actual evaluated `args` in params (undefined args are omitted). `refType` is
`mutation` only on an exact string match, otherwise `query`. A query invalidation
continues immediately. A mutation suspends after its event, including when it
is the last step. The reference holds a promise in `fireMutation` and scripts
true/false outcomes through the transcription's actual await. Generated runs
receive explicit success resumes; `runtime/mutation-outcomes` pins failure,
mixed outcomes, two mutations, a last mutation, intervening field writes,
program replacement and disposal. The refreshed-query scenarios replace query
rows while suspended (0→200 and 2,000→2,100); subsequent sets read the new data.
False ends the run without later effects.
True resumes against current state and the caller's current program inputs.
Native Rust continuations follow ADR 0004; stale/foreign/disposed/consumed
continuations are refused without effects. The reference revokes its opaque
session token on disposal and resolves the outstanding promise false to release
it. No tool is executed. Handler return values are not awaited.

Input measurement is bounded caller setup, never charged to a run's evaluation
work. Runs, resumes and drawing use `PreparedReferenceValues::new`/`with_limits`
for references: one walk, one shared seen-set and one work budget, identical
ceilings and per-entry sizes/refusals. The reference floor is drawing's total
for that supply; refused entries earn no credit and cut only on read. There is
no clamp-then-lazy path or fresh per-entry budget. Unread large/deep references
cannot refuse an unrelated run/resume. Program and retained starting
action/message/form-name measurements still use the core measure; together
with references they form one supply. The floor is the largest combined supply,
not a sum across supplies. Only a raised floor increases the allowance; spent
evaluation work stays spent and state reads retain normal credit.

Borrowed/raw and shared/prepared inputs have identical events, state and failure
points, including runs ending in a cut. Shared programs cache measurement and
statement indexes for the current immutable allocation. A suspended run holds
only a Weak identity: `Arc::make_mut` on a uniquely held program moves it and
invalidates the old measurement without cloning the program. Borrowed programs,
fresh equal programs and alternating Arcs pay bounded measurement per supply,
outside evaluation work. Raw references are prepared once; prepared references
take precedence without preparing unused raw values. Preparation retains the
existing tree lookup representation and caches its measured input token without
walking reference bodies again. PreparedReferenceValues, PreparedProgram, PreparedStart, receipt types and Store
remain Send + Sync.
The reference supplies and prior measurement owners are never retained in the
suspended run. Lazy computed defaults and the current shared-program cache are
run state; neither grows with the number of resumes.

Public regressions complete 1,000/5,000 distinct mutations with borrowed, reparsed,
fresh shared and alternating shared programs; 5,000 outcomes with raw 3,000/30,000
row supplies; and 200 mutations followed by 4,000 filters over 3,000 rows. Allocator
checks bound retained memory for 5,000 freshly fetched equal supplies and separate
O(number of supplies × program bytes) borrowed setup from O(steps) evaluation.
Alternating/growing references cannot enlarge a write beyond a fresh run with the
largest supply: the 5.8 MB write is refused at the same step. Shared/prepared
forms only reduce setup cost. Per-write/event room is released with configured
floor/amplification/hard ceilings enforced, and payload copying costs O(events ×
state read). Reference preparation defaults to a 32,768-level depth bound and
64,000,000 work/size ceilings. An entry over those bounds is recorded as refused,
contributes no bytes, and cuts only a step/prop that reads it. Earlier entries
and work spent preparing them stay accounted; later entries share the remaining
budget. The reference-read grid compares strings from 1 KiB through 70 MiB and

Undefined snapshot entries are omitted before copying or reserving their names.
Cuts and refused writes stop later steps and retain completed effects. Missing/falsy
valueAST, unknown and unowned custom steps skip. Expression scopes refresh

Forms share the Store. No/empty form name stores a top-level wrapped field;
named forms contain fields as `{value,componentType}`. Reads unwrap `value`;
state-marker reads/writes use state directly and create no form entry. A valid
object-valued named form produces `{[formName]:rawFormObject}`; absent, scalar,
array or unnamed forms produce the full snapshot. Wrappers are retained in
payloads, and undefined keys are omitted. Each event captures the state at that
step. `componentType` is metadata. The save flag requests the renderer's extra
save callback independently of a normal store change; Rust returns that flag.
Defaults are component-side effects: while streaming they do nothing; after
settling only an undefined existing value permits a defined default, normally
with save false. `initialize_field_default` implements this guard for unbound
fields, including inherited functions; its ordinary save request is false. Null
counts as an existing value. Private weak identities
retain an undefined wrapper's missing JSON property in this Store; they carry
no action authority, survive retained values/disposal, and cannot be recovered
by JSON reconstruction. A reconstructed object without `value` is ordinary data.

`cargo test` runs all of it without Bun or the network: the reference's outputs are committed as goldens in `conformance/golden/` (full JSON for one-shot results, prompts and edits; an FNV-1a fingerprint per streaming step and per prefix). On a mismatch, the test prints the case, the step and its chunk sizes, and, if Bun is installed, a diff against the reference's JSON.

- **Chunkings:** sizes 1, 2, 3, 4, 7 and 16 code points, two seeded random ones (1 to 16), and two resync sequences that call `set` with growing, rewound and edited text.
- **Sources:** hand-written edge cases; streams recorded from Claude in the viewer, with their chunks as they arrived; every program the reference's own test suites parse, merge and serialize, captured live while they run; the 7 benchmark samples (real GPT output); programs from the upstream docs and examples; fuzz-found cases; synthetic programs up to 30 KB; generated edit patches over every corpus program with a root; and every corpus parse result serialized back to source.
- **Stages:** preprocessing, tokens, statements and expression trees are compared on every prefix of every case, so a mismatch points at the stage that diverged.
- **Invariants:** rules a result should keep, checked on the core and the reference alike over a million generated programs; a rule both parsers break is a candidate quirk (TESTING.md, "Invariants").
- **Rust-only checks:** no input panics, and the deepest shapes run on a 64 KB stack (fixed-seed property tests and `tests/depth.rs`); a streamed program ends where its one-shot parse does, except where the reference itself doesn't (quirks 4, 5, 11 and 19); streaming cost stays linear (`tests/streaming_cost.rs`); results that double at every level are cut at the result-size limit (`tests/size.rs`).

## Message format

`reference/messages.ts` calls the vendored `parseMessage` and `buildMessage`
for [the message cases](conformance/messages.json). The first seven come
from the vendored tests. The others cover CRLF, repeated and unknown marker
lines, markers in ordinary text, URI escapes, JavaScript JSON values and
property order, and lone surrogates. The regeneration script runs the adapter
with `bun --no-install` to write [the goldens](conformance/golden/messages.json).

The Rust test compares written text and complete read results byte for byte.
For each raw or successfully built message it also compares the JSON of every
streaming prefix, including the empty and full prefixes. The adapter uses
JavaScript's UTF-16 slice boundaries. Rust keeps an astral scalar intact when
both units are present and uses the core's reserved U+10F800–U+10FFFF scalars
to carry lone units. Cuts do not split other UTF-8 scalars.

Text that is, or decodes to, a character in U+10F800–U+10FFFF collides with
the core's lone-surrogate representation. This includes percent-decoded
message attributes, literal or escaped scalars in context JSON, and program
string escapes such as `\uDBFE\uDC00`. The four message cases in
[the divergence corpus](conformance/core-divergences.json) pin both sides.
The message fuzzer counts a divergence when replacing those literal scalars
in the reference's serialized reads with the corresponding lone-surrogate
escapes makes the full answer byte-identical. In context JSON those units
can also join adjacent surrogate halves, so the comparison reserializes
the projected context. Other differences still count as findings.

The invariant checks the parts of reversible corpus cases and generated
inputs. Upstream treats a string context as verbatim on write, so a string
that spells valid JSON can read back as a different value. A marker line
inside a body can also start a new section. The golden comparisons cover those
behaviors. The public limit tests cover whole-message admission, nesting in
the winning context, and bounded writing. At the default JSON depth limit
of 800, malformed context still falls back to the original text if the
reader encounters the syntax error within the limit. Entering an 801st
nested container first gives `MessageError::ContextDepth`, even if a later token
makes the context invalid JSON. For example, 801 opening brackets followed
by `oops` are refused here and returned as text upstream.

## Response bundle reader

The core's `parse_response_bundle` ports the renderer package's
`parseResponseBundle`. It reads the winning content of a message, removes
its scripts section, and returns the program, the optional name from the
winning content marker line, Cloud script names in scripts section order,
an opaque revision, the renderer's flags and the scripts error once streaming
ends. Cloud script code is read
for validation and revision construction.

`is_bundle` (`isBundle` in JSON) includes messages without a scripts
section. The renderer sets it when it sees a content marker line in the
original response, recognizes a scripts section, or reads an end marker line
at or after the winning content. A mid-line retry on its own, with no end
marker line or scripts section, reads as a bare program while streaming.

The renderer blocks when `streaming || !complete || error`. A legacy scripts
section can move `complete` from true to false to true while streaming as
the section becomes visible and then valid. A response is settled only
once streaming has ended, `complete` is true, and there is no scripts error.
[Upstream renderer hook](https://github.com/thesysdev/openui/blob/47b9cae0d3b26a8c9d7514d5887a6d6608801ac9/packages/react-lang/src/hooks/useOpenUIState.ts)

The public Rust readers share one string convention. U+10F800–U+10FFFF in
a Rust string stand for lone UTF-16 units U+D800–U+DFFF. Literal or decoded
scalars in that reserved range therefore collide with the corresponding lone
units. Both readers serialize a stand-in as a lone surrogate escape. The
native binding uses the same convention. The WebAssembly binding takes
JavaScript's exact UTF-16 units directly to JSON, which preserves real scalars
in the reserved range as well as lone units. Both bindings encode the
Cloud script names as a JSON array.

The reference adapter calls the unchanged MIT renderer source using
the pinned lang-core message reader. The cases start with inputs from the
renderer's tests. The golden compares the exact UTF-16 path's serialized
fields byte for byte on stored reads and every streaming cut, including the
empty and full prefixes. The public Rust reader checks the same golden outside
the reserved-scalar collisions, which have their own test. Tests also cover
the original response size, JSON depth on the scripts marker line, in the
scripts section and in the winning context, and both bindings.

[Adapter](reference/response-bundles.ts) [Cases](conformance/response-bundles.json)
[Golden](conformance/golden/response-bundles.json)

Compare the opaque scripts revision for equality. Plain UTF-16 name order
makes it equal for the same set of Cloud script names and code regardless of
scripts section order. Upstream's stable sort keeps the section order for
distinct names that its locale comparison ties. This includes canonically
equivalent sequences and names differing only by characters the collation
ignores. Which names tie depends on the JavaScript engine's ICU collation.
The paired cases pin the resulting order dependence for `é` and `e\u0301`
and for `a` and `a\u200b`. For the tested pairs, every upstream equality is
also a core equality, and different sets of names and code have different
core revisions. Individual streaming comparisons use equality classes in
place of the revision text.

## What conformance testing found

In the core, fixed, each pinned by a case:

- Choosing the entry statement must compare with `Query`/`Mutation` by name, not with the reserved-call check (fuzzing, `fuzz/3cdbf706`).
- Two pending statements with the same id in one push lost the second, a regression from making streaming incremental (fuzzing, `fuzz/00951ad8` and nine more).
- `$defs` and `properties` must be read with `Object.entries`, so arrays and strings count by index (`hand/86-odd-schema-shapes`).
- A root element whose `props` is a string, number or boolean is read the way JavaScript reads it (edit fuzzing).
- A prompt spec's maps must be read with `Object.entries` too, so components, functions and actions given as an array or a string list what the reference lists (`library-components-array`, found in 1.0 ticket 08).
- In 1.0 a prop is assigned twice, raw and then validated, so `null` for a param named `__proto__` drops the prototype and then becomes an own prop (fuzzing, `hand/105-proto-named-param`).
- A library call's validated argument replaces the written one only when validation changed it, which the reference sees by identity: an object holding `NaN` (which never equals itself) was rebuilt, losing a duplicate key (a hunt, `fuzz/106fb3f3`).

In the reference, reproduced and recorded in [QUIRKS.md](conformance/QUIRKS.md), each with a draft upstream report (none filed):

1. An apostrophe in unfenced prose ("Here's the UI:") swallows the program.
2. Builtins named after `Object.prototype` members (`@toString`) count as Query/Mutation calls.
3. Prop names that look like numbers take positional args first.
4. Streaming counts redefined statements; one-shot doesn't.
5. A mismatched closing bracket leaves a one-shot result "incomplete" forever.
6. ~~Merging drops a ternary's continuation lines.~~ Fixed in 1.1.0.
7. Prose with an apostrophe before the existing program makes a merge lose it.
8. ~~An id defined twice in the existing program comes out of a merge twice.~~ Fixed in 1.1.0.
9. Serializing drops parentheses around an equal-precedence right operand: `a - (b - c)` becomes `a - b - c`.
10. Serialized object keys aren't quoted (by design since 1.0: the spec says keys must be valid names to round-trip).
11. At a stream's end, a final redefinition that needed closing doesn't win (new in 1.0's terms: the spec says it should).
12. A library function or action called without `@` is still called, even over a component of that name (new in 1.0).
13. Serializing drops the parentheses an operand needs: `!($a && $b)` becomes `!$a && $b` (found by the round-trip invariant).
14. A call parsing made null doesn't count as a null prop, so a required prop isn't checked (found by the round-trip invariant; decided a quirk on 2026-11-09).
15. Merging puts what it appends after an unfinished statement, which takes it in (a candidate, found by the merge invariants).
16. Merging into an empty program returns the patch as it is, deletions and duplicates included (a candidate, found by the merge invariants).
17. While a later statement is still open, finished statements are treated as partial: marked so, and their props checked leniently (a candidate, found by the finished-statements invariant).
18. An empty program parses as incomplete (a candidate, found by the fences invariant).
19. A stray character before a ternary's `?` ends a streamed statement but not a parsed one (a candidate, found by the stream-end invariant).
20. ~~Merging reads comments as code: a quote in a `//` comment can make a patch lose its statements (a candidate, found by the merge invariants).~~ Fixed in 1.1.0.
21. A statement reached through a reference cycle comes out as two different elements, and converting back to source keeps one (new in 1.1, found by the round-trip invariant; its upstream report is drafted as an issue of its own).
22. An open ternary takes in what merging writes after it, so a second merge reads the program differently (new in 1.1, following from its fix for quirk 6; found by the merge-twice invariant; no upstream report).

The long runs against 1.1 (lang-core 1.1 ticket 08) found four candidates, which the maintainer decided on 2026-11-07: two are quirks 21 and 22; one is quirk 4's shape, which the stream-end invariant now recognizes; and the reference throwing a `TypeError` on an object with its own `toString` in a state default stays a [divergence](#divergences), with an upstream report drafted for the maintainer to file.

Also reported, though not a quirk because the core doesn't reproduce it: a few lines that each reference the line before twice make the reference's `parse` take exponential time and memory (ticket 14).

## Divergences

### Query cache lifetime differences

1. After each command an entry exists exactly when a registered query holds its key as current or previous.
2. A query is loading exactly while its current entry has a call in flight.
3. A call delivers success or failure to every query currently on its originating live entry, and a completion with no such reader ends the call without changing data, errors or fetch history.
4. A current entry with neither data nor a call requests one unless the entry has failed and the query already shows an error.

observation to the transition after the last model that still matched upstream.

includes a query once while its status applies, including when a statement uses
the list's name.

### Bounded Store state

Store writes enforce the retained `Limits` result-size ceiling for both individual
values and combined state (ADR 0005). Total state includes JSON-escaped keys and
punctuation; undefined and pristine-only names count as null, aliases count per
occurrence, and empty state costs zero. Per-name cached sizes make updates
incremental. A refusal returns a typed Store error without changing that name's
value, pristine status or version. Binding/form/action writes share this admission
path; a refused reset preserves the whole step. Initialization loads entries that
fit and reports each refusal, including persisted entries. Persisted duplicates
are normalized before pristine flags can change.

This intentionally differs from the reference's unbounded Store. The ordinary
conformance fixtures continue to use the default 8 MiB state ceiling. This state
cap does not establish a peak-memory bound for all intermediate loop/default
shapes; the general amplification follow-up remains unresolved.

streaming EditableTable against `reference/session-data.ts`, generated from the

prefixes. The upstream renderer's unconditional row conversion throws at 15 of
those prefixes because `row.values` is missing/null. Both comparison panes use
that renderer; neither filters partial rows. Their evaluated JSON agrees at every
prefix, so the binding does not add a renderer workaround.

Upstream's `hasDynamicProps:false` shortcut additionally bypasses `ownSteps`:
its click runner emits a finished custom step read from element-shaped data.
The fixture records that event in three observations. The session deliberately
refuses that custom authority, per ADR 0004, while retaining built-in state writes.
`element_shaped_state_query_and_tool_data_runs_builtins_but_cannot_forge_custom_steps`
pins this security divergence in both bindings; tree JSON itself still matches.
No identity is reconstructed from JSON, including function callback results.

Registered functions reuse the runtime's JSON serializer, validation, defaults
and argument caching. Native callbacks run on one ordinary-stack callback thread
per session without a timeout or per-call thread. Its first registration is
checked against the live shared core without mutation, using the same admission
path as registration; thread creation precedes admission to the live core. Accepted implementation
release uses that same stack;
refused registrations and failed/unexecuted handoffs release on the fenced
registering caller, never on the evaluator worker or a grown stack segment.
Same-session reentry on the worker, callback thread or in a host destructor
refuses with Worker; other threads queue, preserving the no-function transport
contract. Callback infrastructure failure revokes the session with a sticky typed
Worker error for the failing callback operation and later calls, including after
disposal. A failed first thread start instead returns Worker without changing
live state, generation or registration room, and a later registration may retry
(#72). A reclaimed handoff receives an explicit error without ending the callback
loop; an already admitted failed handoff still revokes its session, with reason
`host function released before registration`. Ordinary host
throws and contained panics retain function-failure behavior. Normal disposal
remains Disposed; disposal/final drop join both native threads. Public-operation
regressions with infrastructure injection pin caller release, refusal laziness,
registration acknowledgement loss, callback death and shutdown in
`openui-ffi`'s `runtime::tests`; the existing deep-stack and concurrency tests
continue to pin #65. The #73 table-driven test
`registration_preserves_main_errors_precedence_implementations_and_room` compares
22 public registration scenarios with independently captured main f641ded results:
new/replaced/invalid names, name/total-byte/count bounds, replacements at capacity,
disposal and reentry precedence, tree bytes/flags and subsequent admission room.
`live_admission_queries_preserve_room_and_match_real_registration` checks repeated
queries against actual admission on empty and populated live cores. No parser or
evaluator prices, bytes, flags or limits change. Function faults retain Rust's
null and continuing-action semantics, pinned by
`failed_function_results_become_null_and_run_continues_exactly_as_rust`.
`long_callback_matches_rust_and_replacement_destructor_never_queues_to_itself`
pins long-callback output and worker reuse. Host code must return without waiting
on another thread that calls this session. JavaScript callbacks are synchronous;
exotic throw-text coercion failures use the pinned `host function threw` fallback.

A JSON-only host-function result cannot retain the identity of an argument it
returns. Direct Rust `@Echo(@Go())` may return the original marked Go plan;
the JSON callback returning its `value` reconstructs an unmarked plan and loses
the custom step. Restoring that mark from matching JSON would forge authority,
so this is a deliberate security divergence from a direct Rust identity
implementation, pinned by
`json_function_results_cannot_restore_custom_authority_even_from_real_arguments`.
Ordinary JSON-facing implementations compare directly; arbitrary Rust identity-
preserving implementations are not equivalent across a JSON boundary.

Owned and borrowed query/tool supplies use the same core-measured reference
receipt and earn the same input credit. Library-function returns remain computed
results, as on main: the core measures their bodies and reuses those measurements
for validation/projection, while output spends the existing allowance. Crossing
the host JSON boundary does not mint a fresh allowance. This preserves main's
successful callback calls and its existing cuts; ADR 0003's computed-output rule
and ADR 0010's supplied-input accounting apply together.

## Parser materialisation rules (#46, #51, #52, #28)

The `parser/dynamic-*` cases exercise an element-shaped value's own
`hasDynamicProps`: a non-null value wins, with JavaScript truthiness; null and
absence scan props. They cover static and state-reading props, scalar flags and
empty containers, one-shot and under every corpus chunking. The runtime harness
includes these parser cases. Its descriptor streaming matrices no longer start
with an otherwise unnecessary state prop to force a dynamic root.

The `parser/shadow-*` cases cover all 20 built-in call spellings. The reference
compiles built-ins, then library functions, then library actions into one call
registry (`parser.ts:771–777`). Components occupy a separate registry and do not
replace calls. Iterator scoping requires the selected call definition to be a
lazy function (`materialize.ts:188–191`); a library `Each` is not lazy. Library
params then control mapping and validation. This applies in value and expression
positions and through statement references. The lexical rule is independent:
built-in spellings require `@`, except `Action`, even when a component has the
same name (`expressions.ts:132–143`). Actions win when all registries declare a
name. These behaviours match upstream rather than adding a divergence.

The `parser/inherited-*` cases cover all twelve `Object.prototype` names as
schema properties and required entries, optional/required validation, defaults,
enums and supplied own values. An inherited `__proto__` validates as an inert
object; inherited methods validate as functions. Required-only entries see these
names as present. `the_inert_object_prototype_has_a_null_parent` additionally
pins the inherited object's null parent. A null literal assignment removes inheritance in inert object metadata; a later
`__proto__` assignment can then make an own property. No real prototype is accessed or
modified. Literal call arguments use the same assignment rule, and validation
spread copies restore ordinary inheritance (`literal_call_arguments_use_the_same_inert_prototype_assignment`
and `validation_spread_restores_ordinary_inheritance`). The existing divergence
for assigning a new prototype remains.
`reference/parser-materialisation-probe.ts` reproduces the original reports,
all twelve inherited names and the null parent, using the pinned source.

`parser/descriptor-extra-keys` pins `{k:"Str",v:"y",z:2}`: parsing retains the
object and marks the prop dynamic; the reference runtime evaluates it to `"y"`.
Extra keys do not disqualify a recognized expression kind (`ast.ts:111–114`).
This is existing matching behaviour, not a new evaluator change.

For alias chains, cycle membership uses dense slot bits, empty non-memoized
error records are omitted, and reach tracking walks a shared record's children only when that
record becomes live or ceases to be live. Unresolved lists retain singleton-tail
sharing. A null depth-cut entry can be reused only at the same starting depth with
no open reference path; its exact charge, cut count and depth flag are replayed.
Cut containers keep fresh identities at each reach. At raised depth, acyclic
alias tails ending in missing names can jump directly to a cut: the original
per-reference prices and failed lookup are retained, while per-frame successor
marks record each reached slot once. Complete tails and other statement shapes
keep the ordinary cache/walker.
Empty memoized error records remain: even a depth-cut reach with no errors
marks that statement as reported, suppressing a later reach's errors.
`empty_memoized_error_records_preserve_later_reach_suppression` pins this
behaviour against main at default and lowered depth, in both reach orders.
Replay also retains an empty reported marker for memoized depth-cut entries
without unresolved names. Otherwise a late alias can reveal an error suppressed
by an earlier deep reach. Complete empty replays still omit the record, keeping
streaming invalidation linear. `streaming_aliases` pins the review's depth-5 and
default-depth examples and compares 13,500 generated late-alias programs with
fresh parses at each complete-line prefix, including limits and finish.

`conformance/parser-prototype-assignments.json` is a separate twelve-case
divergence corpus. `parser_prototype_divergences` compares complete results with
archived main and pins every 1/3/4/5-character push and finish, alongside the
reference's generated outputs in `golden/parser-prototype-assignments.json`.
Prefixes before the expression is assigned can still differ from main because
ordinary inherited validation now matches upstream (#52). Once `$v` is assigned,
the results must match main exactly. No pending list exempts these cases.
Only inert provenance records that the discarded assignment did not leave an
ordinary prototype; it adds no own field and changes neither value equality nor
Debug/JSON output. Bounded runtime validation retains its existing policy.
Matching this divergence would require inherited AST-field recognition and
evaluator property lookup, beyond the inert ordinary prototype used by #52.
These are representation changes: reference charges, cut points and
ordered errors/unresolved/orphaned names keep their existing rules. The counted
and allocator regressions are described in TESTING.md; their finite bounds do
not establish a universal runtime heap bound (ADR 0008).

### Runtime accounting follow-ups (#44, #47, #49, #50, #54, #55, #62)

`ExpressionEvaluator::supply_input` accepts one program, one starting-input
receipt and one core-prepared reference receipt. Generic size claims and receipt
addition are removed. Program and starting receipts are tied to evaluation
limits; a mismatched receipt is a typed, state-preserving refusal. Measurement
is caller setup and does not spend evaluation work. The largest combined supply
raises one floor; resumed runs retain no supplied reference owners. Drawing
and action runs use `PreparedProgram`'s canonical byte measure. Drawing retains
its prior setup-refusal classification through a separate bounded core check;
that check supplies no second credit value. Measurement of an over-deep branch
retains independently measured input, including bounded structural prefixes;
order does not erase a fitting sibling's credit. Scalar payload state/key reads
earn credit for each changed scalar actually read; consecutive equal scalars earn it once. The latest scalar per name is compared exactly (number bits and string contents), so changing back earns credit again. A container or undefined state read ends that scalar comparison streak. Keys earn credit once per run; output copies still spend work and room.

Typed and data plans earn the same credit for the 301-character concatenation
in `accounting_followups`. Their expression room prices remain different:
604 bytes for typed syntax, 45,753 for descriptor data. The typed evaluator
flattens concatenations; the data evaluator retains its prefix reservations.
Both exact boundaries and the cuts one byte below are pinned. Unifying those
evaluation costs needs a separate representation/traversal change; no prefix
charges are silently removed here. An oversized message unused by a valid
step-array plan is measured but never copied or retained. A default/legacy
message that would be emitted still refuses past its configured ceiling.
Query defaults remain lazy and frozen per action run across resumes, as above.
AST JSON, rather than unavailable original source text, remains supplied input:
compact plans can reach the scaled work ceiling early; the ceiling is never
refreshed by resupply.

Deferred ASTs read from state earn their own measuring work incrementally.
Shared nodes earn credit once, including DAGs with more than 4 GiB of virtual
JSON; every serialized output occurrence is still charged. Fixed work and hard
ceilings remain fixed. Computed `false` projections cost five JSON bytes;
unchanged supplied containers already had that price. The corresponding work
charge also rises by one per affected projection. State, raw query and prepared query
lookups leave depth checks to consumption. A member, length, Count, truthiness or
equality read need not visit unrelated subtrees; coercion and whole-value output
retain their existing depth checks. Input measurement has its own bounded
depth, separate from the expression position. Views remain bound to the
owning evaluation thread because their operations can resume its local account.
Fixed-key marker string predicates borrow their fields without length charges.

Completed streaming defaults have an explicit notification divergence (#45).
Upstream rebuilds some completed containers while later statements arrive;
Rust's parser reuses them. `Store::initialize` preserves Object.is-style identity
for direct callers and cannot infer a parser generation from an identical
container. Synthesizing a notification for every identical pristine container
would break those direct calls; reproducing the full upstream history requires
new parser provenance or different parser reuse/cost. Parsing is kept unchanged.
`streaming_default_notifications` pins both histories for arrays, objects and
expression defaults, including user edits; all values and JSON still agree.
The evaluated-tree streaming harness continues comparing values/errors/JSON,
with notification counts covered by this separate divergence fixture.

Nested element rebuilding keeps main's room accounting. The proposed #55
refund conflicts with the review peak requirement: at rows=3, depth=8 and
room=4,100,000 it raised unique-leaf peak heap from 3,732,632 to 7,472,776

cuts. The refund is deferred; `nested_element_rebuilds_keep_the_existing_room_boundary`
pins the 3,921-byte three-row Box witness at room 10,735, with the adjacent cut.
`review_peaks` pins both review shapes below main's measured peaks. Runtime
arrays release unused growth capacity and rebuilt element props reserve their
known field count. These change allocation capacity, never parser cost, work,
room, output bytes or flags. No general live-memory bound is claimed.

Undefined snapshot members are omitted by `Store::snapshot_json`, matching
upstream persisted JSON and both bindings. This intentionally changes the public

`{}` instead of `{"$x":null}`. Initializing a new Store from that JSON restores
the declared default 5 rather than null; an undeclared undefined name disappears.
The raw snapshot still retains undefined names. The public-interface test
`undefined_snapshot_round_trip_restores_defaults_and_omits_undeclared_names` pins

## Substitution and re-entry accounting review (#49, #64)

Typed syntax, descriptor data and mixed templates use one substitution
traversal. No conversion of an entire template precedes substitution. The
adapters preserve typed copy-on-change, descriptor malformed-data errors and
assignment semantics, and the descriptor-to-typed bridge's extra node charge.
`substitution_preserves_main_values_failures_flags_work_and_room` pins 60
archived-main observations plus every work and room boundary from 0 through
256 for each observation. `nested_loop_memory` retains the independent mapped
component output, allocation and work/room fixtures.

Same-session core `with_scope` re-entry intentionally spends the suspended
owner's work for nested evaluation and projection. In `reentry_accounting`,
`$z`'s state callback re-enters that session in a scope where `$x=100` and
`$y=20`, evaluates `[$x,$y]`, and returns it. The complete result costs exactly
29 work units: four expression visits, four scalar input-measurement visits,
nine inner projection units (including the historical array punctuation
price), four returned-array measurement visits, and eight outer projection
units. Limits 0–28 flag a cut; 29–40 complete with
exact remaining work. The sequential scope releases its projection room, not
its work. This preserves current main's behavior. Earlier code could spend a
temporary suspended account and discard its work/flags; that undercharge is
not restored.

No nested-rebuild room refund is introduced. The existing one-row work/room
thresholds and unique-leaf cut result/peak remain binding (ADR 0008).
The removed `PreparedInput` export is documented in [CHANGELOG.md](CHANGELOG.md);
its replacements have different meanings, so it has no alias.

## Opt-in evaluation-memory accounting (#55)

There is no new divergence at defaults. `Limits::peak_memory()` defaults to
`None`; completed bytes, errors, flags, work, room and pinned allocation-call
counts remain those of main. Explicitly setting it enables the portable arena
reservation measure in [ADR 0011](docs/adr/0011-opt-in-portable-evaluation-memory.md).
The reference has no corresponding allowance. A refused reservation cuts with
`size_limited`; rejected raw recovery values become null, including rejected element envelopes
and owned/revisited rebuilds (#74). A refused write
preserves Store value, pristine status and version. Completed earlier action
steps retain their effects. One memory allowance spans mutation resumes.

The public `peak_memory` tests cover the read and unread `Each(L,i,L)` witnesses,
exact accounted thresholds, monotonic sweeps, parse defaults, descriptors,
reentry, tree rebuilds, atomic cut writes, and the native/wasm session configuration
field. Default CLI differential and same-binary controls are described in
TESTING.md. This resolves #55's two goals for **accounted evaluation storage**;
it does not turn serialized room or portable reservations into a universal heap
bound. The ADR explicitly lists the uncounted paths.

The #74 recovery sweep bounds array-, object- and nested-element-prop cut JSON
by complete JSON plus 32 bytes across all reservation boundaries, for those
tested shapes only. In general a refused array leaves one `null` per admitted
item, so a cut result is bounded by the lengths of the containers already
admitted and never by the raw syntax of what was refused; it can exceed the
complete JSON by more than 32 bytes (a 1,000-item list nested in an object
measured 4,219 bytes against 4,154 complete). The Each
preflight test rejects delaying its vector reservation until after construction
using a same-process heap control. Representative shapes and the 1,000-item
repeated-reference profile enforce heap no greater than the conservative
account for those shapes only. Weights are unchanged. Binding constructors
refuse `referencePreparation.peakMemory` with `LimitExceeded` before creating
session state; omitted settings keep existing behavior. The unused terminal
state-defaults memory-account clear was removed: every evaluation entry that
uses the account initializes its own account before reservations.

## Swift issue #75

Native program replacement is atomic (ADR 0012). Successful shows retain the
same initialization order, per-entry refusals, evaluated bytes and cut flags;
a thrown show preserves both sessions and their preceding drawings/authority.
Malformed element-shaped roots now refuse with the binding's typed Evaluation
error; JSON beyond Swift's existing decoder depth refuses with LimitExceeded,
before commit, rather than a post-replacement Swift decode error. Existing
setProgram/initialize/evaluate are unchanged. The replacement's `nativeView`
restriction is opt-in and adds no evaluation limit to other callers.

Tabs can switch during streaming as local view state. Preview tab selections
are separate from the complete form's selection and cannot run actions or write
state. Unset native dates use an empty system formatter-backed field until a
valid date is entered, then the normal date picker. Writes still normalize to
local midnight and follow the existing binding/form path. Sliders now refuse a
positive step when `(max-min)/step` is nonfinite, including `5e-324` over 0...1;
these use the existing unusable-props fallback instead of snapping to max.
This intentional native refusal prevents an infinite snapping quotient from
turning a midpoint pick into max. Finite large grids keep their tickless native
path; the corpus/galleries gain no fallback.

Regex validation still has no execution-time bound or pattern/subject length
cap. ICU compatibility remainders and invalid-pattern behavior are unchanged;
see the README and TESTING. A length-only cap would not bound backtracking time
and would change valid upstream patterns without solving that problem.

The first runtime missed-mutant batch (#40) adds public-interface checks for
Store and export refusal text, descriptor binding authority, undeclared prepared
supplies, array-like Action arguments, deferred positional/mapped syntax and
unchanged tree bytes/cut boundaries. The directed descriptor truthiness and
array-like action expectations match the vendored 1.1.0 evaluator. No divergence
is added. Replacement tests in the session/native/wasm adapters also pin a
post-evaluation refusal while a Mutation is pending (#77); continuation results,
state and later writes agree with an untouched control. The allocator/layout
margin in the finite memory profiles (#76) changes no portable accounting rule.
