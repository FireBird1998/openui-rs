# Conformance

The `openui-lang` crate is a port of the OpenUI Lang language layer in `@openuidev/lang-core`, the **reference**. Conformance means that for the same input, the core's output is exactly the reference's: byte for byte, not "equivalent".

- **Parse results:** `ParseResult::to_json()` equals `JSON.stringify` of the reference's result, for one-shot parsing and after every push of a streaming parse, with both sides cutting the text at the same code points.
- **Everything else:** the same system prompt string, the same merged program text, the same source from `jsonToOpenUI`, the same enriched errors. Where the reference throws, the core returns an error.

The reference is lang-core 1.1.0, and the core is moving to it ([plan](.scratch/lang-core-1.1/map.md)). What it doesn't match yet is listed case by case in `conformance/pending/` and counted below. The quirks and divergences below were checked against 1.0.1 and are reviewed against 1.1 at the end of the move. The core matched 1.0.1 on every case before the move; that state is the local tag `lang-core-1.0.1`. The 0.3.0 state is the tag `lang-core-0.3.0`. Neither is kept up.

Behaviour that looks wrong in the reference is reproduced anyway and recorded as a [quirk](conformance/QUIRKS.md) with a draft upstream report. The core departs from the reference only where the list of [divergences](#divergences) below says so, all on inputs no real program produces.

Cases the core doesn't match yet would be listed in `conformance/pending/`, one list per test; the line above counts them. A listed case may fail, and one that matches again fails its test until it's taken off the list.

`cargo test` runs all of it without Bun or the network: the reference's outputs are committed as goldens in `conformance/golden/` (full JSON for one-shot results, prompts and edits; an FNV-1a fingerprint per streaming step and per prefix). On a mismatch, the test prints the case, the step and its chunk sizes, and, if Bun is installed, a diff against the reference's JSON.

- **Chunkings:** sizes 1, 2, 3, 4, 7 and 16 code points, two seeded random ones (1 to 16), and two resync sequences that call `set` with growing, rewound and edited text.
- **Sources:** hand-written edge cases; streams recorded from Claude in the viewer, with their chunks as they arrived; every program the reference's own test suites parse, merge and serialize, captured live while they run; the 7 benchmark samples (real GPT output); programs from the upstream docs and examples; fuzz-found cases; synthetic programs up to 30 KB; generated edit patches over every corpus program with a root; and every corpus parse result serialized back to source.
- **Stages:** preprocessing, tokens, statements and expression trees are compared on every prefix of every case, so a mismatch points at the stage that diverged.
- **Invariants:** rules a result should keep, checked on the core and the reference alike over a million generated programs; a rule both parsers break is a candidate quirk (TESTING.md, "Invariants").
- **Rust-only checks:** no input panics or overflows a 512 KB stack (fixed-seed property tests and the deepest shapes); a streamed program ends where its one-shot parse does, except where the reference itself doesn't (quirks 4, 5, 11 and 19); streaming cost stays linear (`tests/streaming_cost.rs`); results that double at every level are cut at the size cap (`tests/size.rs`).

## Differential fuzzing

`scripts/fuzz.sh` runs generated and mangled programs through the core and a long-lived reference process and compares fingerprints of the one-shot result, the tokens and every push of a random chunking. `scripts/fuzz.sh --edits` does the same for merges (programs with patches made from them) and serialization (real parse results, sometimes with fields deleted, retyped or renamed), comparing full outputs. ## What conformance testing found

In the core, fixed, each pinned by a case:

- Choosing the entry statement must compare with `Query`/`Mutation` by name, not with the reserved-call check (fuzzing, `fuzz/3cdbf706`).
- Two pending statements with the same id in one push lost the second, a regression from making streaming incremental (fuzzing, `fuzz/00951ad8` and nine more).
- `$defs` and `properties` must be read with `Object.entries`, so arrays and strings count by index (`hand/86-odd-schema-shapes`).
- A root element whose `props` is a string, number or boolean is read the way JavaScript reads it (edit fuzzing).
- A prompt spec's maps must be read with `Object.entries` too, so components, functions and actions given as an array or a string list what the reference lists (`library-components-array`, found in 1.0 ticket 08).
- In 1.0 a prop is assigned twice, raw and then validated, so `null` for a param named `__proto__` drops the prototype and then becomes an own prop (fuzzing, `hand/105-proto-named-param`).
- A library call's validated argument replaces the written one only when validation changed it, which the reference sees by identity: an object holding `NaN` (which never equals itself) was rebuilt, losing a duplicate key (a hunt, `fuzz/106fb3f3`).

In the reference, reproduced and recorded in [QUIRKS.md](conformance/QUIRKS.md), each with a draft upstream report (none filed):

1. An apostrophe in unfenced prose ("Here's the UI:") swallows the program.
2. Builtins named after `Object.prototype` members (`@toString`) count as Query/Mutation calls.
3. Prop names that look like numbers take positional args first.
4. Streaming counts redefined statements; one-shot doesn't.
5. A mismatched closing bracket leaves a one-shot result "incomplete" forever.
6. ~~Merging drops a ternary's continuation lines.~~ Fixed in 1.1.0.
7. Prose with an apostrophe before the existing program makes a merge lose it.
8. ~~An id defined twice in the existing program comes out of a merge twice.~~ Fixed in 1.1.0.
9. Serializing drops parentheses around an equal-precedence right operand: `a - (b - c)` becomes `a - b - c`.
10. Serialized object keys aren't quoted (by design since 1.0: the spec says keys must be valid names to round-trip).
11. At a stream's end, a final redefinition that needed closing doesn't win (new in 1.0's terms: the spec says it should).
12. A library function or action called without `@` is still called, even over a component of that name (new in 1.0).
13. Serializing drops the parentheses an operand needs: `!($a && $b)` becomes `!$a && $b` (found by the round-trip invariant).
14. A call parsing made null doesn't count as a null prop, so a required prop isn't checked (a candidate, found by the round-trip invariant).
15. Merging puts what it appends after an unfinished statement, which takes it in (a candidate, found by the merge invariants).
16. Merging into an empty program returns the patch as it is, deletions and duplicates included (a candidate, found by the merge invariants).
17. While a later statement is still open, finished statements are treated as partial: marked so, and their props checked leniently (a candidate, found by the finished-statements invariant).
18. An empty program parses as incomplete (a candidate, found by the fences invariant).
19. A stray character before a ternary's `?` ends a streamed statement but not a parsed one (a candidate, found by the stream-end invariant).
20. ~~Merging reads comments as code: a quote in a `//` comment can make a patch lose its statements (a candidate, found by the merge invariants).~~ Fixed in 1.1.0.

Also reported, though not a quirk because the core doesn't reproduce it: a few lines that each reference the line before twice make the reference's `parse` take exponential time and memory (ticket 14).

## Divergences

Documented, not emulated. None occurs in the corpus, and none comes from a real model's output.

| Input | Reference | Core |
|---|---|---|
| Nesting 257 to about 8,000 levels | parses (throws `RangeError` past that) | stops at 256, sets `depth_limited` |
| A result past about 8 MiB of JSON (statements inlined until it doubles per level) | parses quickly, since 1.1 builds each statement once and shares it, but its JSON doubles per level: about 1 GB at 22 levels, and at 24 `JSON.stringify` runs out of memory | cuts it, sets `size_limited` |
| An object assigned to `__proto__`, or `null` in an object literal | replaces the prototype; later reads and `in` checks see through it | ignores the assignment (`null` for a param named `__proto__` is reproduced) |
| An object literal shaped like an element used as the root | returns that object as `root` | `root` is `None` (it still counts as a root, so no `no-root`) |
| An object literal shaped like an AST node used as the root (`root = {k: "Comp", name: "Card", args: []}`) | returns that object as `rootExpression` when it holds a component call, and throws a `TypeError` when a node in it lacks the children its kind has (`root = {k: "Comp"}`) | no `rootExpression`, and `no-root` |
| A state default sorting text outside ASCII with `@Sort` (accents, other scripts) | orders it with ICU's root collation (`localeCompare`) | orders ASCII exactly as ICU does, other characters by code point after it |
| A state default sorting more than 65 values whose comparison loops (numbers and text mixed: `2 < "10" < "1a" < 2`) | JavaScriptCore merges sorted runs | a stable merge sort. Up to 65 values it follows JavaScriptCore exactly, and either way the core never panics |
| A state default reading a property of a built-in method or prototype (`$a = [].map.length`, `$b = $o.__proto__.x`) | that property | `undefined` (the method itself, `[].map`, is reproduced) |
| An object literal shaped like an AST node in a state default (`$x = {k: "Num", v: 1}`) | evaluates it as that node | keeps it as the object |
| A state default turning an object with its own `toString` or `valueOf` into text (`$a = {toString: 1}` then `$b = $a + ""`, or in `@Sort`, `@Filter`'s `contains`, `==`) | `parse` throws a `TypeError`: the object can't become text | `"[object Object]"` |
| JSON nested deeper than 800 levels, for `json_to_openui` or `parse_json` | handled, up to the engine's recursion limit | refused with an error |
| `1e400` in JSON read back | `Infinity` | refused: a `serde_json::Value` can't hold it |
| A component with `properties` whose `required` is neither an array nor a string (a number, say) | throws a `TypeError` building the library (`required.includes is not a function`) | treats `required` as empty |
| A library function or action without `params`, or one that isn't an object | throws a `TypeError` building the library | has no params |
| A slot schema whose `anyOf` or `oneOf` isn't an array of objects (`anyOf: [null]`, `oneOf: "x"`) | throws a `TypeError` validating a value in it | treats the slot as one that takes data |
| An action shape in `$defs` that refers to itself, such as `ActionExpression: {anyOf: [{$ref: "#/$defs/ActionExpression"}]}` | recurses until the engine's stack overflows (`RangeError`) building the library | leaves that `$ref` in place |

Error messages where the reference throws aren't compared, only that it throws. For system prompts, the reference's own error messages are compared exactly. Where it crashes inside the JavaScript engine instead (a `TypeError`, for a spec that's a JSON array, say), the core only has to return an error too.

## Reproducing

```bash
scripts/check.sh                        # everything above, without Bun
scripts/regen-golden.sh                 # recompute every golden from the vendored reference (Bun)
scripts/import-corpus.sh [<checkout>]   # re-import upstream programs and test calls, then regenerate
scripts/update-reference.sh <commit>    # vendor another upstream commit, then import and regenerate
scripts/fuzz.sh --seed 1 --count 10000  # parse fuzzing (Bun)
scripts/fuzz.sh --edits --seed 1 --count 10000
```
