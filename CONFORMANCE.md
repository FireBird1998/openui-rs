# Conformance

The `openui-lang` crate is a port of the OpenUI Lang language layer in `@openuidev/lang-core`, the **reference**. Conformance means that for the same input, the core's output is exactly the reference's: byte for byte, not "equivalent".

- **Parse results:** `ParseResult::to_json()` equals `JSON.stringify` of the reference's result, for one-shot parsing and after every push of a streaming parse, with both sides cutting the text at the same code points.
- **Everything else:** the same system prompt string, the same merged program text, the same source from `jsonToOpenUI`, the same enriched errors. Where the reference throws, the core returns an error.

**Moving to lang-core 1.0.** The reference below is 1.0.1, but the core still mostly behaves as it did for 0.3.0, the last version it fully conforms to (the local tag `lang-core-0.3.0`). The move lands ticket by ticket ([map](.scratch/lang-core-1.0/map.md)), and the pending lists hold what differs until then. The divergences and quirks below were written against 0.3.0, and the move's last ticket reviews them against 1.0.

Behaviour that looks wrong in the reference is reproduced anyway and recorded as a [quirk](conformance/QUIRKS.md) with a draft upstream report. The core departs from the reference only where the list of [divergences](#divergences) below says so, all on inputs no real program produces.

Cases the core doesn't match yet would be listed in `conformance/pending/`, one list per test; the line above counts them. A listed case may fail, and one that matches again fails its test until it's taken off the list.

`cargo test` runs all of it without Bun or the network: the reference's outputs are committed as goldens in `conformance/golden/` (full JSON for one-shot results, prompts and edits; an FNV-1a fingerprint per streaming step and per prefix). On a mismatch, the test prints the case, the step and its chunk sizes, and, if Bun is installed, a diff against the reference's JSON.

- **Chunkings:** sizes 1, 2, 3, 4, 7 and 16 code points, two seeded random ones (1 to 16), and two resync sequences that call `set` with growing, rewound and edited text.
- **Sources:** hand-written edge cases; every program the reference's own test suites parse, merge and serialize, captured live while they run; the 7 benchmark samples (real GPT output); programs from the upstream docs and examples; fuzz-found cases; synthetic programs up to 30 KB; generated edit patches over every corpus program with a root; and every corpus parse result serialized back to source.
- **Stages:** preprocessing, tokens, statements and expression trees are compared on every prefix of every case, so a mismatch points at the stage that diverged.
- **Rust-only checks:** no input panics or overflows a 512 KB stack (fixed-seed property tests and the deepest shapes); a streamed program ends where its one-shot parse does, except where the reference itself doesn't (quirks 4 and 5); streaming cost stays linear (`tests/streaming_cost.rs`); results that double at every level are cut at the size cap (`tests/size.rs`).

## Differential fuzzing

`scripts/fuzz.sh` runs generated and mangled programs through the core and a long-lived reference process and compares fingerprints of the one-shot result, the tokens and every push of a random chunking. `scripts/fuzz.sh --edits` does the same for merges (programs with patches made from them) and serialization (real parse results, sometimes with fields deleted, retyped or renamed), comparing full outputs. ## What conformance testing found

In the core, fixed, each pinned by a case:

- Choosing the entry statement must compare with `Query`/`Mutation` by name, not with the reserved-call check (fuzzing, `fuzz/3cdbf706`).
- Two pending statements with the same id in one push lost the second, a regression from making streaming incremental (fuzzing, `fuzz/00951ad8` and nine more).
- `$defs` and `properties` must be read with `Object.entries`, so arrays and strings count by index (`hand/86-odd-schema-shapes`).
- A root element whose `props` is a string, number or boolean is read the way JavaScript reads it (edit fuzzing).

In the reference, reproduced and recorded in [QUIRKS.md](conformance/QUIRKS.md), each with a draft upstream report (none filed):

1. An apostrophe in unfenced prose ("Here's the UI:") swallows the program.
2. Builtins named after `Object.prototype` members (`@toString`) count as Query/Mutation calls.
3. Prop names that look like numbers take positional args first.
4. Streaming counts redefined statements; one-shot doesn't.
5. A mismatched closing bracket leaves a one-shot result "incomplete" forever.
6. Merging drops a ternary's continuation lines.
7. Prose with an apostrophe before the existing program makes a merge lose it.
8. An id defined twice in the existing program comes out of a merge twice.
9. Serializing drops parentheses around an equal-precedence right operand: `a - (b - c)` becomes `a - b - c`.
10. Serialized object keys aren't quoted.

Also reported, though not a quirk because the core doesn't reproduce it: a few lines that each reference the line before twice make the reference's `parse` take exponential time and memory (ticket 14).

## Divergences

Documented, not emulated. None occurs in the corpus, and none comes from a real model's output.

| Input | Reference | Core |
|---|---|---|
| Nesting 257 to about 8,000 levels | parses (throws `RangeError` past that) | stops at 256, sets `depth_limited` |
| A result past about 8 MiB of JSON (statements inlined until it doubles per level) | exponential time and memory, or a huge JSON | cuts it, sets `size_limited` |
| An object or `null` assigned to `__proto__` | replaces the prototype; later reads and `in` checks see through it | ignores the assignment |
| An object literal shaped like an element used as the root | returns that object as `root` (lang-core 1.0 no longer does) | `root` is `None` |
| A schema default object, mutated by one parse | shared with later parses | copied per parse |
| JSON nested deeper than 800 levels, for `json_to_openui` or `parse_json` | handled, up to the engine's recursion limit | refused with an error |
| `1e400` in JSON read back | `Infinity` | refused: a `serde_json::Value` can't hold it |
| A component with `properties` whose `required` is neither an array nor a string (a number, say) | throws a `TypeError` building the library (`required.includes is not a function`) | treats `required` as empty |

Error messages where the reference throws aren't compared, only that it throws. For system prompts, the reference's own error messages are compared exactly. Where it crashes inside the JavaScript engine instead (a `TypeError`, for a spec that's a JSON array, say), the core only has to return an error too.

## Reproducing

```bash
scripts/check.sh                        # everything above, without Bun
scripts/regen-golden.sh                 # recompute every golden from the vendored reference (Bun)
scripts/import-corpus.sh [<checkout>]   # re-import upstream programs and test calls, then regenerate
scripts/update-reference.sh <commit>    # vendor another upstream commit, then import and regenerate
scripts/fuzz.sh --seed 1 --count 10000  # parse fuzzing (Bun)
scripts/fuzz.sh --edits --seed 1 --count 10000
```
