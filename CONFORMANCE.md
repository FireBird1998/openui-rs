# Conformance

The `openui-lang` crate is a port of the OpenUI Lang language layer in `@openuidev/lang-core`, the **reference**. Conformance means that for the same input, the core's output is exactly the reference's: byte for byte, not "equivalent".

- **Parse results:** `ParseResult::to_json()` equals `JSON.stringify` of the reference's result, for one-shot parsing and after every push of a streaming parse, with both sides cutting the text at the same code points.
- **Everything else:** the same system prompt string, the same merged program text, the same source from `jsonToOpenUI`, the same enriched errors. Where the reference throws, the core returns an error.

The reference is lang-core 1.1.0 (OpenUI Lang 1.1), and the core matches it on every case in the corpus: nothing is pending. The quirks and divergences below were checked against 1.1.0 on 2026-11-06, and quirks 21 and 22 added on 2026-11-07. Three quirks were fixed upstream in 1.1, and the core follows. The core conformed to 1.0.1 and to 0.3.0 before; those states are the local tags `lang-core-1.0.1` and `lang-core-0.3.0`, and aren't kept up.

Behaviour that looks wrong in the reference is reproduced anyway and recorded as a [quirk](conformance/QUIRKS.md) with a draft upstream report. The core and runtime depart from the reference only where the list of [divergences](#divergences) below says so. The runtime representation divergence can arise when evaluating an action value.

`reference/runtime.ts` runs the pinned parser, store and tree evaluator, with
no function implementations and with the schema's action definitions. JSON
Schema cannot carry upstream's in-memory binding marks; binding configuration
is #35's work. Its runtime library uses the compiled component prop shapes.
Persistence is generated from the full case's declared names and value shapes
using Mulberry32 seeded by FNV-1a of `<case>:persisted`, and reapplied on every
initialize. The persistence map is JSON-round-tripped before use: its saved
JSON defines its values, non-finite normalization and absence of cross-name
aliases on both sides. Defaults and persistence each retain their own store per stream.
Both scenarios replay all core chunkings, including resets and recorded deltas.
Runtime cases may additionally declare `referenceValues` (query/mutation data)
and `stateValues` (explicit embedder state applied after generated persistence).
Both are plain JSON in the case manifest and apply to both scenarios. The
reference adapter uses lang-core's actual `createQueryManager(null)`, registers
mutations, registers normalized query nodes with `evaluateQueries`, and reads
results before anything runs. It supplies no provider or refresh interval and
always disposes the manager. Normalization uses statement ids as inert tool
names and null args, since registration/read semantics are all that is tested.
`queryManager.ts:389` skips incomplete nodes; `:468–472` reads defaults or null;
`:508–531` registers fresh mutations with `{status:"idle"}` and `:606–607` reads
them. Defaults are evaluated by the adapter's declaration resolver, as the
manager's `toQueryNode` evaluates defaults using its caller context (`:145–157`).
`registerMutations` also resets an existing mutation to
`{status:"idle",data:null,error:null}` when its tool name changes (`:517–522`).
A renderer retaining one manager can observe that transition while a
`Mutation("…` statement streams in, before anything has run. This harness
creates a fresh manager per observation and uses statement ids as inert tool
names, so that history-dependent transition is not observed or modelled here.
The runtime does not retain a query manager; an embedder can supply its result.

These are lang-core's observable pre-execution results. The supplied overlay is
ours: own `referenceValues` entries for declared query/mutation ids win,
including null, false and empty containers, standing in for loaded data.
Declaration lookup is independent of textual order and loop scope. Undeclared
names do not resolve, but admitted supplied entries still contribute input size.

Both parsers currently set every query statement's `complete` to true, even
when streaming auto-close completed its syntax (`parser.ts:204`, Rust
`parser.rs`'s QueryStatement constructor). Their global `meta.incomplete` does
not identify which query is unfinished. The explicit `queryComplete:false`
corpus fixture tests the registration rule using the public statement metadata;
we do not infer per-query completeness from global metadata or source text.
Actual unfinished-query detection remains unavailable from the parse result.
The renderer consumes the same true flag, so this currently creates no
observable query-result mismatch with it.
Prepared supplied values have separate bounded iterative sizing; unread or
undeclared refused values cannot cut unrelated evaluation. The prepared form
reuses the measurement and a cached core value representation across evaluations,
including when read. Containers stay shared; scalar strings are converted once.
Full output construction and actual operations still draw on work, room and
depth. Numeric sizing allocates no string.
Only evaluated trees, runtime errors, snapshots and their JSON are compared;
notification counts, snapshot identity and versions are outside this harness.
In particular, issue #45's extra upstream notifications for rebuilt completed
container defaults do not affect these comparisons.

The runtime additions live in `conformance/runtime.json`, in the corpus's
normal format, without enlarging the parser corpus. They cover state props,
inlined references and cycles, nested objects and structural ASTs, a 64-element
deep tree, failures with statement and inline attribution, malformed descriptors, and a default that
changes an already evaluated prop as it streams. The review additions cover
long concatenations, numeric descriptor fields, missing call arguments,
array-like arguments, invalid collections, Assign-shaped data, strict name lookups,
non-string and malformed descriptor fields, element-shaped state, and an independent
failed prop alongside an action. The #34 additions cover loops, components,
root expressions and references, with caller context pinned by quirk 25. Coverage is the union of both
scenarios and all prefixes; state reads count actual runtime `getState` calls,
and statement references are measured on the preprocessed source AST with
`Each` locals excluded. The original 859 cases have 261 cases with dynamic
props, 62 reading state, 426 referencing statements and 11 with runtime errors.
Only 2 of the 152 recorded cases declare state. That measurement is why the
runtime additions are needed.

Runtime goldens are compact JSON in `conformance/golden/runtime/`: full results
for each one-shot scenario and FNV-1a per streaming step. Identical scenario
fingerprint arrays are shared via `persisted: "defaults"`. Runs are a hash for
one step or `[hash,count]` for two or more equal consecutive hashes. Adjacent
equal runs and invalid counts fail the test. Existing cases read `sizes` and
`ops` from the core's goldens rather than copying them; step counts and missing
or extra chunkings are checked. Runtime-only cases retain their own plans. A mismatch names the case,
scenario, step and plan, with a JSON diff when Bun is available, or the hashes,
Rust JSON and an exact `bun --no-install runtime.ts show ...` command otherwise.

`pending/runtime.json` has one primary feature reason per case, with the latest
required ticket chosen first (#38, #36, #35, then #34). Each reason needs both
reference evidence and an independent Rust AST/plan witness. There is no
pending-list update mode: matching entries, unknown names and wrong reasons
fail the test. The same removal rule applies to the separate visible divergence
list. Assign-shaped data has the explicit `35:assign-descriptor` reason: its
non-binding result requires the #35 getState/marker rule. All pending one-shot
observations still compare snapshots, existing-root metadata, and every root
or nested element prop whose raw value contains no deferred feature. Completed
#34 features no longer mask those props. The runtime receives the parsed
library so declared functions and actions retain their existing feature
classification; this harness supplies no function implementations. The counts
above include rooted observations even when all their props are deferred.
Partial prop comparison is one-shot: streaming expected results are hashes;
a second per-step projection oracle would add substantial fixture size and
regeneration work. Whole-result streaming comparisons remain unchanged. Filtered
runs also reject a selected pending case that now matches.
Counts and coverage above are checked by `tree_conformance.rs`.

Regenerate from `reference/` with `bun --no-install runtime.ts golden`. Two
complete regenerations were byte-identical; the measured command takes about
105 seconds here. Run-length encoded runtime goldens use about 11.3 MB,
plus the roughly 0.3 MB focused interface golden. The general regeneration script also
runs this harness and requires cached dependencies; it never installs packages.

The reference uses `Object.is` (NaN equals NaN; signed zeros differ). Upstream
has no version. The fixture's `mappedVersion` counts listener notifications,
plus one deliberate runtime extension: disposing nonempty state advances the
version even though upstream clears its listeners without notifying. Pristine
metadata changes and empty disposal do not advance it. Snapshot identity is
checked separately, including replacement on empty disposal. Disposal always
clears; at version exhaustion the version stays at its maximum.

`cargo test` runs all of it without Bun or the network: the reference's outputs are committed as goldens in `conformance/golden/` (full JSON for one-shot results, prompts and edits; an FNV-1a fingerprint per streaming step and per prefix). On a mismatch, the test prints the case, the step and its chunk sizes, and, if Bun is installed, a diff against the reference's JSON.

- **Chunkings:** sizes 1, 2, 3, 4, 7 and 16 code points, two seeded random ones (1 to 16), and two resync sequences that call `set` with growing, rewound and edited text.
- **Sources:** hand-written edge cases; streams recorded from Claude in the viewer, with their chunks as they arrived; every program the reference's own test suites parse, merge and serialize, captured live while they run; the 7 benchmark samples (real GPT output); programs from the upstream docs and examples; fuzz-found cases; synthetic programs up to 30 KB; generated edit patches over every corpus program with a root; and every corpus parse result serialized back to source.
- **Stages:** preprocessing, tokens, statements and expression trees are compared on every prefix of every case, so a mismatch points at the stage that diverged.
- **Invariants:** rules a result should keep, checked on the core and the reference alike over a million generated programs; a rule both parsers break is a candidate quirk (TESTING.md, "Invariants").
- **Rust-only checks:** no input panics, and the deepest shapes run on a 64 KB stack (fixed-seed property tests and `tests/depth.rs`); a streamed program ends where its one-shot parse does, except where the reference itself doesn't (quirks 4, 5, 11 and 19); streaming cost stays linear (`tests/streaming_cost.rs`); results that double at every level are cut at the result-size limit (`tests/size.rs`).

## What conformance testing found

In the core, fixed, each pinned by a case:

- Choosing the entry statement must compare with `Query`/`Mutation` by name, not with the reserved-call check (fuzzing, `fuzz/3cdbf706`).
- Two pending statements with the same id in one push lost the second, a regression from making streaming incremental (fuzzing, `fuzz/00951ad8` and nine more).
- `$defs` and `properties` must be read with `Object.entries`, so arrays and strings count by index (`hand/86-odd-schema-shapes`).
- A root element whose `props` is a string, number or boolean is read the way JavaScript reads it (edit fuzzing).
- A prompt spec's maps must be read with `Object.entries` too, so components, functions and actions given as an array or a string list what the reference lists (`library-components-array`, found in 1.0 ticket 08).
- In 1.0 a prop is assigned twice, raw and then validated, so `null` for a param named `__proto__` drops the prototype and then becomes an own prop (fuzzing, `hand/105-proto-named-param`).
- A library call's validated argument replaces the written one only when validation changed it, which the reference sees by identity: an object holding `NaN` (which never equals itself) was rebuilt, losing a duplicate key (a hunt, `fuzz/106fb3f3`).

In the reference, reproduced and recorded in [QUIRKS.md](conformance/QUIRKS.md), each with a draft upstream report (none filed):

1. An apostrophe in unfenced prose ("Here's the UI:") swallows the program.
2. Builtins named after `Object.prototype` members (`@toString`) count as Query/Mutation calls.
3. Prop names that look like numbers take positional args first.
4. Streaming counts redefined statements; one-shot doesn't.
5. A mismatched closing bracket leaves a one-shot result "incomplete" forever.
6. ~~Merging drops a ternary's continuation lines.~~ Fixed in 1.1.0.
7. Prose with an apostrophe before the existing program makes a merge lose it.
8. ~~An id defined twice in the existing program comes out of a merge twice.~~ Fixed in 1.1.0.
9. Serializing drops parentheses around an equal-precedence right operand: `a - (b - c)` becomes `a - b - c`.
10. Serialized object keys aren't quoted (by design since 1.0: the spec says keys must be valid names to round-trip).
11. At a stream's end, a final redefinition that needed closing doesn't win (new in 1.0's terms: the spec says it should).
12. A library function or action called without `@` is still called, even over a component of that name (new in 1.0).
13. Serializing drops the parentheses an operand needs: `!($a && $b)` becomes `!$a && $b` (found by the round-trip invariant).
14. A call parsing made null doesn't count as a null prop, so a required prop isn't checked (found by the round-trip invariant; decided a quirk on 2026-11-09).
15. Merging puts what it appends after an unfinished statement, which takes it in (a candidate, found by the merge invariants).
16. Merging into an empty program returns the patch as it is, deletions and duplicates included (a candidate, found by the merge invariants).
17. While a later statement is still open, finished statements are treated as partial: marked so, and their props checked leniently (a candidate, found by the finished-statements invariant).
18. An empty program parses as incomplete (a candidate, found by the fences invariant).
19. A stray character before a ternary's `?` ends a streamed statement but not a parsed one (a candidate, found by the stream-end invariant).
20. ~~Merging reads comments as code: a quote in a `//` comment can make a patch lose its statements (a candidate, found by the merge invariants).~~ Fixed in 1.1.0.
21. A statement reached through a reference cycle comes out as two different elements, and converting back to source keeps one (new in 1.1, found by the round-trip invariant; its upstream report is drafted as an issue of its own).
22. An open ternary takes in what merging writes after it, so a second merge reads the program differently (new in 1.1, following from its fix for quirk 6; found by the merge-twice invariant; no upstream report).

The long runs against 1.1 (lang-core 1.1 ticket 08) found four candidates, which the maintainer decided on 2026-11-07: two are quirks 21 and 22; one is quirk 4's shape, which the stream-end invariant now recognizes; and the reference throwing a `TypeError` on an object with its own `toString` in a state default stays a [divergence](#divergences), with an upstream report drafted for the maintainer to file.

Also reported, though not a quirk because the core doesn't reproduce it: a few lines that each reference the line before twice make the reference's `parse` take exponential time and memory (ticket 14).

The tree harness visibly classifies `runtime/nested-undefined` under the
nested-undefined divergence: an undefined own `toString` field disappears in
Rust, so upstream's failed prop becomes a successful coercion. It also
classifies `spec/evaluation/008-builtin-sort-locale` under the existing non-ASCII
sorting divergence. Neither is hidden on a future feature's pending list.

The former blanket malformed-descriptor divergence is removed. Numeric Member
fields, absent/null call arguments, array-like argument objects, invalid
collections and entries, and lazy malformed branches have reference cases.
`runtime/malformed-data-ast` now matches, including `number is not iterable`.
The one named remaining diagnostic difference is `runtime/descriptor-map-target`.
All runtime divergences commit both reference and Rust outputs for both
state scenarios in `conformance/divergences/runtime-<reason>.json`. The test
checks each complete output, so neither side may widen silently. For the map
target only, a normalizer additionally checks equality after changing just the
single pinned error message. It asserts its exact case name and reason and
cannot apply to general comparisons or other divergence entries.
It avoids adding engine-specific invalid-member inspection to the core failure
channel. Other descriptor errors are compared byte for byte.

The runtime divergence is pinned by `nested_undefined_normalization_can_suppress_one_store_change`
and the explicitly excluded case in `openui-runtime/tests/store.json`. JSON,
parsing and bindings cannot represent nested undefined. Parity would require
changing the evaluator and value model together under a separate ADR, rather
than adding a runtime-only variant to the parser's public enum.

Core entry-point errors where the reference throws compare only that it throws. The runtime `root-expression-throw` divergence also pins the exception's name and message. For system prompts, the reference's own error messages are compared exactly. Where it crashes inside the JavaScript engine instead (a `TypeError`, for a spec that's a JSON array, say), the core only has to return an error too.

## Reproducing

```bash
scripts/check.sh                        # everything above, without Bun
scripts/regen-golden.sh                 # recompute every golden from the vendored reference (Bun)
scripts/import-corpus.sh [<checkout>]   # re-import upstream programs and test calls, then regenerate
scripts/update-reference.sh <commit>    # vendor another upstream commit, then import and regenerate
scripts/fuzz.sh --seed 1 --count 10000  # parse fuzzing (Bun)
scripts/fuzz.sh --edits --seed 1 --count 10000
```


Pending one-shot comparison also checks the ordered errors belonging to
independent props. An error identifies its component, optional statement and
prop, but has no tree path. If multiple elements share that identity, errors
are compared only when every corresponding raw prop is in scope; an identity
shared with an out-of-scope prop cannot be separated reliably. Snapshots and
independent prop values remain checked as before.

The runtime case `runtime/state-descriptor-default` pins a parser difference
outside #34: a declared `$x={k:"Num",v:5}` is interpreted as an AST by the
reference's state-default path and becomes 5, while Rust preserves the object.
Its separate `parser-state-descriptor-default` divergence commits both complete
outputs, and the tree harness witnesses the raw Rust declaration and reference
snapshot. #34 leaves parsing unchanged. Runtime descriptor tests use explicit
`stateValues` to isolate tree behavior from this difference. Other runtime
additions cover all loop-item kinds, nested loops, shadowing in either lookup
order, deferred item capture (pending #36), component collections and branches,
root outcomes, and absent/defaulted/supplied/forward query and mutation reads.

The `root-expression-throw` runtime divergence pins a lang-core `TypeError`
(`No default value`) escaping `evaluateRoot`. The reference driver records
its name and message. Rust returns no root and a `runtime-error` attributed to
`root`, preserving that cause. A successful non-element still gets `no-root`.
Both one-shot state scenarios are fully pinned; this case has no pending feature.

The second review's additions exercise all twelve shared `Object.prototype`
names as component descriptors in element state, loop-built elements and
supplied query data, including argument failures before the failed builtin
call. `runtime/substitution-errors` pins malformed loop templates against the
reference, including map callbacks naming `substituteRef` and missing children
reporting `node.k`. The separate `runtime/substitution-map-target` case pins the remaining
call-target wording difference for a non-callable own `map:3` on each of the
three collections (array elements, object entries and call args). Both complete
outputs are committed; no other case or pending feature receives that allowance.
The typed and descriptor substitution walkers remain separate: consolidating
traversal requires refactoring the typed walker used by parsing, which this

Per-item inline replacements retain their room reservation while buffered.
The owning expression releases that footprint immediately before its public
projection charges it, retaining the original computed/data representation's
pricing. Nested argument projections release only their own reservations;
work and cut flags remain spent. `tree_replacement_room_and_inherited_calls` pins the exact element room
thresholds and limits buffered replacements to the available room, including
when a prop needs nested evaluation. It also checks prepared list and string
reads under fixed work limits and that prepared claims cannot finance output.
Inherited non-callable builtins evaluate arguments in order without retaining
an argument record that cannot be consumed; a large-array test bounds that
otherwise discarded buffer too.
