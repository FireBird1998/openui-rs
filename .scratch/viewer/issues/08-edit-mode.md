# 08 — Edit mode

**What to build:** On a screen that came from a live stream or a recording, the maintainer can send a follow-up request. The model gets the edit-mode system prompt, which the core generates with its edit-mode option, and answers with a patch. As the patch streams in, the core merges it into the current program (the binding gains merging), and the viewer redraws the merged program. The patch is shown beside the merged program. Follow-ups can be recorded. A follow-up's recording includes the program it patched, so replaying it reproduces the merge.

**How it works:**
- **Asking for a change.** Once a screen from a live request or a recording has fully arrived, its bar offers "Follow Up". The sheet asks for the change, keeping the program's library.
- **The prompt** is the library's prompt spec with `promptOptions.editMode` on, generated by the core. It asks for only the statements that change.
- **The message** gives the current program in a code block, then the change. No earlier turns are sent, so thinking blocks and history checks don't come into it.
- **Each step** merges the patch received so far into the program and parses the result one-shot, through `mergeAndParse` on the core thread. A merge isn't append-only, so the stream session isn't used. Stepping back and the kept steps work as before.
- **The text pane** splits into "Patch", with what's been received, and "Merged program", at the shown step.
- **Chaining.** The whole program once arrived, merged for a patch, becomes the base for the next follow-up.
- **Recordings** of a follow-up add `patchOf`, the program the patch applies to. A recording with `patchOf` opens as a patch to it. The format note on `Recording` covers this.
